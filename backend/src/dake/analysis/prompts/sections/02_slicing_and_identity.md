# 事项切片与跨轮身份

1. **按独立验收目标切片**
   - 先按具体业务对象、诉求目标、发生轮次和独立验收结果切分语义片段。
   - 单条消息包含多个可独立验收的目标时拆分为多个候选；同一业务目标不得为了覆盖多个分类标签而重复建项。

2. **跨场景事项身份延续**
   - 换群讨论、换人跟进、跨多天、类型标签增加/移除/更正、正常业务阶段推进（如咨询→报价→交付→验证）均不改变事项身份（`event_id`）。
   - “又失败”“还是不行”本身不证明新发生轮次；无明确恢复记录时优先延续可认回的原事项。

3. **主题键（`topic_key`）与疑点保底**
   - `topic_key` 简明表达 `产品或对象/具体资源或环境/问题或目标`，不使用群号、日期或单独分类名充当主题；更新旧事项时可采用本轮准确称呼，不必逐字复用旧 `topic_key`。
   - 仅当存在会改变事项身份、作用对象或发生轮次的实质歧义且现有上下文无法消歧时，才标记待人工确认并在 `decision_reason` 中写明具体疑点。
