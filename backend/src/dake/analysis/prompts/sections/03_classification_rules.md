# 分类标签与逐类最低证据门槛

只允许使用以下标签：`商机`、`流失`、`排障`、`资源需求`、`功能需求`、`商务需求`、`其他`。若事项真实成立，但任何标签均无充分证据且无法排除六类主标签，必须使用 `type="待分类"`、`classification_status="待分类"`、`type_labels=[]`，严禁用 `其他` 兜底证据不足的事项。

- **商机**
  - 成立门槛：有具体业务对象，且存在新增采购、增购、付费扩量或以采购为目的的试用评估。
  - 排除边界：泛问价格、未表明采购目的的技术试用、内部运维扩容不算商机；试用≠购买，报价≠成交。
- **流失**
  - 成立门槛：有具体合作/产品对象，且存在减少用量、停用、迁离或不续约方向（含条件性离开风险、明确计划或实际执行）。
  - 排除边界：普通抱怨、催办、正常续费、临时测试切流不算流失。
- **排障**
  - 成立门槛：现有产品/服务/环境出现异常、失败、性能退化，或其定位、处置、恢复与验证。
  - 排除边界：恢复既有预期行为属排障；内部为修复故障扩容属于排障处置而非客户资源需求；严禁猜测未证实的根因。
- **资源需求**
  - 成立门槛：在现有产品能力范围内，明确申请或交付容量、配额、规格、带宽、机器、实例、地域等资源（即使具体数量尚在测算也可成立）。
  - 排除边界：申请≠批准≠交付；单纯性能抱怨而无明确资源诉求不标资源需求。
- **功能需求**
  - 成立门槛：要求新增、开放、改变或改善产品对外可感知的能力、交互、范围或新性能目标（改善已有功能亦可成立）。
  - 排除边界：单纯询问当前是否支持某项能力不算功能需求。
- **商务需求**
  - 成立门槛：具体报价、合同、折扣、续费手续、终止手续、账单核对、开票、付款、退款等答复与办理。
  - 注意事项：客户的付款陈述≠到账核实，需按实际证据分别记录。
- **其他**
  - 成立门槛：仅当真实可跟进的服务责任已成立（如专项使用培训、上线前书面适用性核验），且能用直接证据排除上述六类主标签时使用，必须在 `other_reason` 中提供排除理由及逐字引文。
