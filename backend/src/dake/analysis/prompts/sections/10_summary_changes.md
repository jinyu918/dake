# 局部摘要更新与变化记录（changes）

每个候选通过 `changes` 记录本轮新增事实及其直接证据，每项结构为 `{kind, text, evidence: [{message_id, quote}], replaces}`：

1. **变化类型（`kind`）**
   - `progress`：新的排查结果、处置动作及效果、影响范围、负责人、状态流转或承诺变化。
   - `confirmation`：新的测试或反馈再次确认现状（例如“今天再试仍失败”），`replaces` 固定为 `null`，记录核实进展但摘要可以不变。
   - `correction`：有明确本轮依据纠正旧结论，保留历史，不把猜测当成确认。

2. **引文与局部演进纪律**
   - `text` 是一条简短客观事实，保留未确认、怀疑、请求等限定词；`evidence` 必须引用本轮直接证据的连续原文，不可把历史背景引文充当新增事实依据。
   - `new` 必须有初始事实，`summary` 概括初始问题；`duplicate` 与 `review` 的 `changes` 固定为 `[]`；没有新增事实、仅重述或换措辞时 `changes=[]`（已有原归属时应选 `duplicate`）。
   - `update` 的 `summary` 字段不用于整体覆盖旧摘要，程序只采用有依据的 `changes` 局部更新：
     - 新增事实通常 `replaces=null`，由程序追加简短事实并保留原问题、重要进展和未解决事项；
     - 确有依据更新摘要中已过时或错误的片段时，`replaces` 必须逐字复制那个旧片段并由 `text` 替换它，不得为润色删除未解决事项或把局部新反馈替换成整段摘要。
   - 同一事件同批的全部有效进展都必须列入 `changes`，不能只留下最后一条；迟到旧陈述只补证据，不能覆盖较新结论。
