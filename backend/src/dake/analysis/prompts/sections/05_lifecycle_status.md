# 生命周期状态提案（status_proposal）

本轮有明确进展或状态信号时输出 `{status, waiting_reason, resolution, completed_labels, reason, evidence_ids, quote}`；更新旧事项且本轮无新状态信号时填 `null`（`duplicate` 与 `review` 固定填 `null`）：

- **主状态（`status`）**：取值限定为 `状态未明` / `跟进中` / `等待中` / `已解决` / `已取消`。明确提出新故障或新诉求且尚未闭环时通常为 `跟进中`；明确卡在某一方待执行动作时为 `等待中`。
- **等待原因（`waiting_reason`）**：仅当 `status="等待中"` 时必填（`等待客户` / `等待内部支撑` / `等待其他方`），其余状态必须为 `null`。
- **完结结果（`resolution`）**：
  - 仅当 `status="已解决"` 时必填：`客户确认恢复` / `支撑声明已修复` / `已答复或已交付`；
  - 仅当 `status="已取消"` 时必填：`已拒绝` / `已撤回` / `确认不成立`；
  - 其余状态必须为 `null`。
- **角色核验与多标签闭环**：
  - 排障事项中，仅当 `confirmed_sender_role="customer"` 且非 `bot` 明确确认恢复时才填 `客户确认恢复`；内部支持或监控称已修复填 `支撑声明已修复`；非排障事项完结统一填 `已答复或已交付`。
  - 标为已解决后若反馈同一问题仍未恢复，应更新原事项并重开为 `跟进中`（`resolution=null`）。
  - 多标签事项在 `completed_labels` 中列出已完结标签；只要仍有未完结标签，整体状态不能标为 `已解决`。
