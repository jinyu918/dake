# 增量抽取与证据纪律

1. **增量触发与证据范围**
   - 只依据本轮 `new_messages` 带来的新事实、明确诉求或实质进展产生候选；`context_messages`、`existing_events` 与 `history_context` 仅用于语义消歧和历史关联。
   - 每个候选的 `evidence_ids` 必须至少包含一条 `new_messages` 的完整消息 ID（含来源前缀，如 `official_chat:...`），且仅允许引用本次输入的 `new_messages` 或本轮人工讨论直接关联的 `context_messages`，严禁引用未提供原文的历史 ID 或仅出现在 `history_context` 中的消息。

2. **多标签独立举证与撤销纪律**
   - 每个采用的类型标签必须在 `type_labels` 中单独列出，提供独立的 `evidence_ids` 和连续原文子串 `quote`；`type` 为兼容主标签，必须包含在 `type_labels` 中（`待分类` 事项的 `type_labels` 固定为空列表 `[]`）。
   - 本轮明确更正先前误判标签时，在 `removed_types` 中逐项提供被撤销标签及本轮更正 `quote`；没有明确纠正依据时，不得仅因本轮未重提某标签而删除它。

3. **无效闲聊过滤与连续分条消息拼合**
   - 纯问候、表情、单纯“收到/谢谢/辛苦了”、全程无任何文字说明的孤立附件占位符、无现实业务对象的泛泛知识问答不建事项，也不据此判定事项已完成或故障已恢复；没有有效事项时返回 `candidates=[]`。
   - 若群内围绕同一事项分多条连续发送（例如先发请求 ID 列表、报错日志、域名/参数代码块或 `[图片]`/`[文件]` 占位符，紧接着发“帮查下这几个”“就是上面那个”），必须将这些紧邻的前置/后置消息一并纳入该候选的 `evidence_ids`，禁止只保留最后一句口语提问而漏掉前面的参数、日志或配图记录。

4. **机器人通知辅助边界（`sender_kind`）**
   - `sender_kind` 来自本地已确认账号配置，与内部/外部人员身份无关；`unknown` 不等于机器人，不得直接过滤。
   - `bot` 消息只能作为辅助证据，纯告警或自动恢复通知不能独立创建或更新客户事件，也不能把自动恢复通知当成人工确认恢复。
   - 候选必须由本轮非机器人消息中的明确问题、诉求、影响讨论、排查或处理事实支持；客户单方明确反馈即可产生事件，不要求内部回复。
   - 不能因为同一窗口有人说话、问候或回复“收到”，就将无关告警转成客户事件；人工讨论确实引用或涉及告警时，可以附上相关机器人证据。
