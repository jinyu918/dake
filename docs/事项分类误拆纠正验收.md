# 事项分类同轮误拆纠正验收

验收日期：2026-11-17。范围：第七阶段 A30 已误拆为 E/E2 后的人工身份纠正。使用自行构造的消息、固定 Provider、正式增量服务及 HTTP；未调用真实取数或模型接口，未读取业务 `.env` 或真实聊天。

## 1. 交付结果与适用范围

已补齐正式入口：`POST /api/v1/events/{event_id}/same-round-corrections`。在同一客户事务内核对 E/E2 的预期版本、操作编号、操作人、理由、同轮确认、对象范围及带 digest 的恢复更正依据，然后保留 E，将 E2 记为 `corrected_into=E`。

A30 回归实际先执行报障、恢复、再次发生，形成两个正式身份；随后执行有据的恢复撤销，再提交同轮纠正。结果为两个存储记录、一个默认跟进目标。E2 的 ID、原状态、证据、人工操作及旧修订仍在；不物理删除，也不把它改成“已完成”。

本入口限定于已经记录为 E 的复发子项。两侧当前恢复记录必须已按证据撤销；仍有恢复事实的 A29 被拒绝。无复发关系的独立事项、跨客户、跨分析流、自身、别名链、反向纠正均不能借此入口并入。未增加业务表、依赖、批量归并或任意事项合并入口。

## 2. 保存、查询与后续增量

- 默认事件列表、类型筛选及客户事件计数只统计保留身份；直接查询 E2 仍返回原身份和保留项定位。页面旧 URL 不会自动切换到列表首项。
- E/E2 各追加一条人工修订并增加版本，保存同一份纠正收据。原 `updated_by` 前缀、旧快照和旧 digest 不改写。
- 两侧任一版本过期返回 409；相同操作编号、相同请求返回原收据，换内容则冲突。第二侧保存失败时两侧及收据一起回滚。
- `GET /api/v1/events/{event_id}/same-round-corrections/{operation_id}` 取得客户锁后读取结果。只有锁取得且确无收据时才返回 `not_committed`，不把锁等待中的操作报成已确认未提交。
- 自动跟进候选与匹配排除 E2；已知别名引用解析到 E，正式解析过程记录 `corrected_alias_to_retained` 及身份映射。E2 的普通字段写入返回指向 E 的 409。
- 同主题、缺少新发生边界的 `new` 转待核对，避免立即生成 E3。真正恢复后再次发生的用例仍建立独立新轮次并关联 E。
- 旧周期沿用原快照投影；纠正生效之后的新周期只投影 E，并可包含人工纠正。新收据显式保存人工修订引用，旧收据的恢复方式和原结果保持不变。

## 3. 字段、人工历史及关系

E2 的事实带原事项和原事实 ID 导入 E，导入 ID 按来源确定生成；`replaces`、采用、锁定及问题引用映射到导入 ID。证据保留来源事项标识。E2 的原 `manual_operations` 和 `updated_by` 不拼接成 E 的历史，来源人工决定另存并展示，原项仍可直接核对。

兼容事实可带入；公共字段或相同环节、范围、业务时间的互斥值保留为建议和待核对问题。人工未知、清空、不适用是已表达的决定，不当成默认缺值覆盖。已撤销标签及其归档属性不因导入重新生效，失效版本及已拒绝/历史事实不能通过逐字段处置重新采用。

单侧兼容锁定随事实保留。冲突锁定、不能自动带入的锁定以及锁定的恢复结论必须逐字段选择事实、填写理由，并逐项确认两侧全部受影响锁定。缺少确认时整个纠正失败；没有批量解锁开关。

E2 的误拆复发关系记为 `retracted`，保存撤销依据和操作编号，后续依据复核不会重新确认它。保留项已有前次关系保留；导入的自指关系标为待核对，独立第三方关系继续保留，未重写整个关系图。

纠正依据后来被修订时，保留项提示人工身份决定待复核；不自动恢复 E2 为活动身份，也不自动拆出新项。原消息版本恢复后仍能复核，历史收据和纠正审计不被改写。

## 4. 长消息缺陷的修复

主会话独立复现：E2 的对象名称出现在长消息第 160 字之后，当前证据摘要看不到对象，但正式候选的完整源消息、变化及版本均可核对。原实现仅查 `event.evidence[*].excerpt`，错误返回 400。

新增三分支回归首次结果为 **1 failed、2 passed**，正例确实复现该 400。修复后，程序按两侧原证据的来源、消息 ID、digest 和发送时间安全回取当前准确版本，在完整正文中核对范围。没有延长或伪造 excerpt，也没有用人工理由代替证据。

三分支分别验证：对象在摘要截断之后仍成功；一侧完整源消息确无该对象时拒绝；完整正文仍含对象但消息版本已经变化时拒绝。成功前后的旧修订、证据 digest 及源消息 digest 均保持原值。三个新增实库用例也使用对象位于长消息末尾的输入。

## 5. 页面与提交结果不明

纠正对话框展示双方版本、字段事实和证据，可选择恢复更正依据，填写范围、操作人、理由并确认同轮边界；涉及锁定时可逐字段处置。

409 保留草稿，提供明确的双方刷新操作。提交应答丢失或 503 时冻结表单，先核对固定操作编号的收据；确认已提交后刷新到别名详情。确认未提交后只能重试原请求；需要编辑时先重新读取双方版本并生成新操作编号。浏览器回归核对重试前后请求内容和编号完全相同。

页面中的操作人是本地填写的审计标签，未增加账号认证或授权系统。

## 7. 验证期间发现的问题

1. 最初 A30 已误拆纠正回归因缺少接口返回 404；新增正式事务入口后通过。
2. 组合增量回归发现纠正后的关系标识会再产生一次自动修订；提交时统一核对关系标识，并停止向别名写入证据复核修订后通过。
3. 第一轮全量后端为 739 passed、1 failed、37 deselected；失败是精确 OpenAPI 操作清单未加入新接口，已同步期望值并重新生成客户端。最终全量结果见上表。
4. 长消息正例实际返回 400，按第 4 节修复并重跑专项、全量及完整实库。
5. 新增浏览器回归实际发现确认未提交后仍可编辑原操作请求；修复为固定请求重试，最终 4 项通过。
6. 前端首次全量为 60 passed、1 failed、8 skipped；字段裁定 409 丢失“本次未追加裁定”提示。已恢复该提示并保留别名定位信息，重启最终源码的合成服务后全量通过。
7. 实库准备先遇到 Windows 转发就绪超时、旧端口占用检查及隔离实例 `partial_revokes` 与镜像初始授权不兼容。上述尝试均未进入 pytest，均已清理。最终使用 WSL 专用回环端口和镜像默认授权模式，由验收脚本验证精确测试库授权后运行完整 32 项；未把环境准备失败记为产品用例通过。

## 9. 结论的边界

A30 已误拆分支的正式人工纠正、可追溯旧身份及后续单目标跟进已通过本报告所列合成验收。固定 Provider 负责提供候选和语义判断，这些结果不代表真实模型已经正确理解任意自然语言、环境范围或误拆事实。

同主题且没有可核对新边界的候选保守进入待确认；已验证真实恢复后复发可新建，未据此声称所有不同范围的新发生都能自动识别。纠正依据编辑后只标复核，未实现自动撤销身份纠正或通用拆并引擎。第六阶段报告中的 A09 通用计算、A20 相对日期归一化和其他未验收能力不在本阶段补齐范围内。
