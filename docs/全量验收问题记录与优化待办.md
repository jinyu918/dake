## 三、待办事项清单（下一阶段迭代收口）

### P0：工程与任务调度稳定性（已完成，未改变分析流版本，无需重跑存量数据）

- [x] **1. 重启/中断恢复时的任务中心游标与数据库权威水位对齐**
  - **现象**：任务中心出现 `已进入实时或已有更晚结果，旧历史不能倒灌主流`（压测重启期间触发 `26` 次）。
  - **根因**：工作线程已将窗口原子提交至 `uid_pipeline_state.analyzed_until`，但服务重启打断了协调线程末尾的 `save_execution`，重启后 `TaskService` 按滞后 1 窗的 `child.cursor` 重复派单，被 `PipelineRepository.acquire()` 防倒灌锁拒绝（底层 `block_reason` 为空，数据无损）。
  - **已落地**：在 [services/tasks.py](file:///d:/projects/dake-aftersales/backend/src/dake/services/tasks.py) 的 `select_customers`、`_drain` 与 `_fail_or_retry` 中增加 `_pipeline_progress` 同流向权威水位对齐，自动追平已提交游标并清除假防倒灌标记。
- [x] **2. 高并发 MySQL 瞬时死锁（错误码 `1213`）轻量重试与其余 `ORDER BY` 巡检**
  - **现象**：8 并发工作线程同时更新状态时偶发 MySQL `1213` 锁冲突，导致单窗记为普通失败待下轮重试。
  - **已落地**：在 [mysql.py](file:///d:/projects/dake-aftersales/backend/src/dake/repositories/mysql.py) 单语句自动提交操作与 [runs.py](file:///d:/projects/dake-aftersales/backend/src/dake/repositories/runs.py) `_claim` 槽位抢占事务中增加 `1205/1213` 毫秒级退避重试，并将 [tasks.py](file:///d:/projects/dake-aftersales/backend/src/dake/repositories/tasks.py) `list()` 改为先排主键再取正文。
- [x] **3. 默认并发参数合理化**
  - **现象**：[config.py](file:///d:/projects/dake-aftersales/backend/src/dake/config.py) 原默认 `ANALYSIS_SLOTS=2, LIVE_RESERVED=1` 导致历史追赶仅剩 `1` 个通用槽位。
  - **已落地**：默认调整为 `ANALYSIS_SLOTS=6, LIVE_RESERVED=1, FETCH_AHEAD=6`，并已同步至 `.env.example`。

### P1：模型输出合约与解析容错（已完成，未改变分析流版本，无需重跑存量数据）

- [x] **4. 群内连发消息引文与相邻 `message_id` 自动对齐 + `changes` 证据自动补入 `evidence_ids`**
  - **现象**：客户 1 分钟内连发多条短消息时，模型偶发摘录第 2 条消息的逐字原话却写成紧邻第 1 条的 `message_id`，或在 `changes` 引用了本轮新消息但漏同步写入顶层 `evidence_ids`（全量累计触发 `11` 次）。
  - **已落地**：在 [attribution.py](file:///d:/projects/dake-aftersales/backend/src/dake/analysis/attribution.py) 新增 `_pre_normalize_attribution_json()`，仅当非短词引文在候选池/当前窗口中**唯一精确匹配**时自动对齐 `message_id`，并将已核验的本轮新消息自动补入顶层 `evidence_ids`（多处模糊匹配或伪造引文仍严格拒绝）。
- [x] **5. `typed_attributes` 同类型同名属性重复输出的合并容错**
  - **现象**：长排障对话中模型偶发在同一候选输出两条同名属性（如两条 `排障.症状与对照表现`），触发 `同一类型的属性名称不得重复`（累计触发 `4` 次）。
  - **已落地**：在 [contract.py](file:///d:/projects/dake-aftersales/backend/src/dake/analysis/contract.py) 中按顺序保留最新一条作为主展示值、合并 `evidence_ids`，并将前序片段归档入 `extensions.demoted_typed_attributes`。
- [x] **6. `update` 混入旧上下文证据 / 未变属性重提 / `correction` 漏填 `replaces` 的柔性清洗**
  - **现象**：`update` 旧事件且已具备本轮新消息证据时，模型偶发把 `context_messages` 旧消息 ID 混入顶层 `evidence_ids`、重复输出旧窗口已提取的 `typed_attributes`，或在 `kind="correction"` 时漏填 `replaces`（累计触发 `7` 次）。
  - **已落地**：在 [attribution.py](file:///d:/projects/dake-aftersales/backend/src/dake/analysis/attribution.py) `_pre_normalize_attribution_json()` 中，当候选已含合法本轮新消息时自动剥离混入顶层的旧上下文 ID 与未变化旧字段；`correction` 的 `replaces=null` 时自动降级按 `progress` 追加。
