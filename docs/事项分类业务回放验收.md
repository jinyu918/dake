## 3. 复现与修复

### 3.1 分类依据修订及 HTTP 查询

原逻辑在摘要变化为空时直接返回，遗漏同一标签的新证据。现在独立检测分类和属性证据变化，保存分类修订。同值属性的新依据也可追加；保存层生成 evidence_refs，含来源、消息 ID、群、发送时间、digest 和当时引文，不改变 Provider schema 4.0。

新增 classification 修订原本超出 HTTP EventRevision.change_kind 枚举，造成响应校验失败。现在同步 API 枚举、OpenAPI、生成客户端及前端“分类依据更新”文案。正式两轮回放生成该修订后，事件列表、详情、周期详情及变化接口均返回 200。前端还验证摘要与事项级证据均未变时，仅分类依据改变也保留时间线条目。

证据：test_classification_replay.py 中 test_adding_evidence_to_an_existing_label_saves_without_summary_change；test_classification_queries.py 中 test_classification_only_revision_is_returned_by_event_and_cycle_queries；eventTitle.spec.ts、savedChanges.spec.ts。

### 3.2 撤销后重采用

首轮排障与资源需求并存、目标 1000；次轮先撤销资源需求，再重新采用并提供目标 2000。原 restrict_fields 因撤销历史仍有该标签而丢弃新属性。现在按归并后的当前标签过滤，保留标签、新专属属性及扁平兼容值、重采用依据、撤销历史和快照。

证据：test_re_adopting_a_label_later_in_the_same_batch_preserves_its_removal_history。没有删除撤销历史规避问题。

### 3.3 纠正、冲突与正常进展的有限处理

同批 1200 后的正式 correction 若与新字段证据同源且变化文本含新值 900，可采用 900。未解的不同目标数量保留原采用值并标具体字段待核实；跨轮资源“目标总量与增减量”也与已保存值比较。后续纠正仅消除对应程序冲突标记，旧快照保留。

补充修复了字段旧值没有写入摘要的场景：跨轮已保存 1200，或本批先填 1200 后更正 900，若摘要仅记录办理进展，不能因为 replaces 找不到就拒绝整个窗口。合并时保留逐字段旧值及更正位置，要求同一字段确有不同旧值、replaces 包含该旧值、新字段及更正引文同源且引文范围重叠、更正引文同时含新旧值、变化文本含新值；旧值也不能已经出现在原摘要或本批待写入的摘要片段中。只有这些条件均成立且替换片段完全不存在时，才保存字段更正和带原 replaces 的变化记录，保留原摘要及旧版本。同批先追加且能唯一定位的摘要片段仍按既有路径局部替换。

新增两个正例分别验证跨轮与同批只改字段、摘要保持可核对范围、兼容属性同为 900、旧修订不变且更正依据保留。八个反例覆盖无关 replaces、同消息另一事实的引文、缺少已知旧字段、旧值已在原摘要、本批追加或替换后的摘要中、替换片段重复，以及非 correction；均仍抛 ContractError 并回滚本窗口。没有把任意缺失 replaces 放行。该窄化分支不能代替对真实更正对象的语义判断。

两项字段“审批、交付与可用验证”“上线与需求验证结果”允许正常进展，无须伪标 correction。测试同时覆盖同批与跨轮的“申请已受理 → 已获批待交付”和“部分通过 → 按条件验证通过”，旧快照仍在。

证据均在 test_classification_replay.py：

- test_same_batch_explicit_field_correction_resolves_a_typed_attribute_conflict
- test_field_only_correction_preserves_summary_without_the_old_quantity（同批、跨轮）
- test_field_only_correction_does_not_accept_an_unverifiable_replacement（八类拒绝边界）

### 3.4 迟到隔离与版本依据

字段按自身消息和发送时间过滤，不能借同批新进展覆盖当前值；专属及扁平兼容属性一起受限。事项级引文截断不妨碍完整字段引文定位。既有消息编辑、历史背景、未来版本拒绝及恢复撤销回归继续通过。

## 6. 精确未完成项

1. A36 人工确认、锁定、解除锁定、冲突复核未实现；A30 误拆后的人工并回也未完成。
