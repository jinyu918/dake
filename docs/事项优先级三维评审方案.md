# 事项优先级三维评审方案

**事项定级顺序：先按影响面和客观时限查基础档，再按客户等级提档，接着应用客户情绪和催办规则，最后判断是否超时。机器人告警按受影响客户等级直接定为 P1、P2 或 P3。**

## 1. 影响面 × 客观紧迫度：定基础档

影响面看已证实的业务后果、范围和能否绕行；客观紧迫度看是否需要立即止损或有明确业务时限。报告方等级和催促语气都不作为影响面证据。

| 影响面 | 立即止损 | 尽快，有明确近时限 | 常规，可计划 | 时限不明 |
| --- | --- | --- | --- | --- |
| 严重：大范围关键生产中断且无绕行，或正在发生重大安全、资损事故 | P0 | P0 | P0 | P0 |
| 高：核心生产链路受阻，未达 P0 条件 | P1 | P1 | P1 | P1 |
| 中：局部降级、部分用户受影响或有可用绕行 | P1 | P2 | P2 | P2 |
| 低：咨询、一般需求、无当前生产影响的调整 | P2 | P2 | P3 | P3 |
| 未知：信息不足 | 待评估 | 待评估 | 待评估 | 待评估 |

P0 只由已证实的严重影响触发，不因客户级别、催办或等待超时产生。有重大故障迹象但证据不足时，优先人工复核。

## 2. 客户等级：区分谁报告、谁受影响

事项采用报告客户和已确认受影响客户中的最高**有效**等级，事项归属仍是原报告客户。受影响客户需根据故障证据、经核实的客户反馈或人工确认来认定。共用服务出问题，不代表所有客户都受影响；证据不足时标记「影响客户待核实」，暂不按该客户提档。

| 有效等级 | 基础 P0 | 基础 P1 | 基础 P2 | 基础 P3 | 基础待评估 |
| --- | --- | --- | --- | --- | --- |
| `L9/L10` | P0 | P1 | P1 | P2 | 待评估 |
| `L6–L8` | P0 | P1 | P2 | P3 | 待评估 |
| `L0–L5` | P0 | P1 | P2 | P3 | 待评估 |
| 未知或过期 | P0 | P1 | P2 | P3 | 待评估 |

`L9/L10` 提一档且封顶 P1；`L6–L8` 相较普通客户用更短时限和同档靠前体现优先。有效等级按数值降序，待确认不等于 `L0`。

## 3. 紧急程度：客户情绪、催办与处理时限

- **客户情绪明显升级，至少按 P1 响应。** 客户本人就当前事项明确表达强烈焦虑或愤怒，例如「我已经等得受不了了，现在请给我一个明确答复」。业务影响尚未查清时，响应按 P1，影响仍标为「待评估」。
- **强催办时，P3 提为 P2。** 客户本人就同一事项重复催办或要求升级处理，情绪尚未明显升级。基础影响待评估的事项优先复核。单句「尽快」、表情、内部转述和机器人通知不单独触发提档。
- **待接手**：从首条有效提报起算，重开从本轮重开起算。明确负责人和下一步才算接手；「收到」、机器人回复、自动分配或单纯转交均不算。
- **待进展**：从有效接手或最近一次实质进展起算。诊断结果、已执行的处置或已落实的下一步才重置；客户催促、重复转述不重置。

下表每格为「待接手 / 待进展」。按客户等级、情绪与催办调整后的档位选择时限，不因本次超时升档反复重算。

| 计时前档位 | `L9/L10` | `L6–L8` | `L0–L5` 或待确认 | 到期动作 |
| --- | --- | --- | --- | --- |
| P0 | 立即 / 30 分钟 | 同左 | 同左 | 保持 P0，标记超时 |
| P1 | 30 分钟 / 1 小时 | 45 分钟 / 2 小时 | 1 小时 / 2 小时 | 保持 P1，标记超时 |
| P2 | 1 小时 / 2 小时 | 2 小时 / 4 小时 | 4 小时 / 8 小时 | P2 → P1 |
| P3 | 2 小时 / 4 小时 | 4 小时 / 8 小时 | 8 小时 / 16 小时 | P3 → P2 |
| 待评估 | 1 小时内复核 | 2 小时内复核 | 4 小时内复核 | 标复核超时，不猜级 |

P0 和 P1 生产故障按自然时间，其余按约定的服务时间。到期仍无接手或进展时，即使没有新消息，也按表执行。同一次连续超时只升一档。阶段内因客户等级、情绪或业务影响提档时，从原计时起点核算新的时限。

等待内部支撑继续计时；明确向客户或第三方索取必要材料且有下次复查时间时，可暂停非持续生产故障的进展计时，复查到期仍提醒。已解决或取消停止，重开重新起算。人工锁不改写；仍标记超时、保留建议；重大新证据走紧急人工复核。

**待办排序**：未完结优先 → 处理档位 → 同档已超时优先 → 有效客户等级从高到低 → 情绪明显升级优先，其次是强催办 → 最早到期优先。尚未定处理档的事项单独按风险和复核截止时间排序。

## 4. 机器人告警按客户等级定优先级

| 已确认受影响客户等级 | 告警优先级 | 处理方式 |
| --- | --- | --- |
| `L9/L10` | P1 | 最高优先告警队列，提醒值班或 TAM |
| `L6–L8` | P2 | 大客告警队列，交对应客户负责人跟进 |
| `L0–L5` | P3 | 普通告警队列，默认聚合展示 |
| 归属不明、等级未知或过期 | 待归属／待定级 | 内部兜底队列，不静默、不当作普通客户 |

同一告警影响多个客户时，按已确认的最高等级处理，未核实的客户继续核实。告警首次触发或确认影响更高等级客户时，按对应档位通知。同一轮告警的重复消息合并到原记录，达到约定的提醒间隔后再提醒。自动恢复仅结束对应轮次的机器人告警，后续复发按新一轮处理。平台重大告警沿用既有值班安排。

## 5. 典型场景

| 场景 | 处理结果 |
| --- | --- |
| `L3` 报障，证实同一故障也使 `L9` 核心生产链路受阻 | 归属仍为 `L3`，按高影响、有效等级 `L9` 处理为 P1；达严重影响红线才是 P0 |
| `L3` 局部降级，只有「可能波及大客」，时限常规 | P2，标影响客户待核实，不做 `L9` 提档 |
| 同一局部降级后来确认 `L9` 也受影响，影响仍为中、时限仍为常规 | 基础 P2 不变，有效等级改取 `L9`，处理档升为 P1 |
| `L10` 常规咨询，单句「尽快」 | 基础 P3，等级提档 P2，不因语气再升 |
| `L6` 低影响请求，客户明确要求负责人介入，但未表现出明显的情绪升级 | 强催办 P3 → P2，不抬高影响面 |
| `L3` 事项影响还没查清，客户说「等得受不了了，请现在给我一个明确答复」 | 响应按 P1，业务影响仍待评估 |
| `L8` P2 到了 2 个服务小时，无人接手，也没有新消息 | 升为 P1 |
| `L8` 事项已等了 1 个服务小时，期间因客户情绪升为 P1，接手时限为 45 分钟 | 从原提报时间核算，保持 P1 并标记超时 |
| `L9` P1 生产故障一直等内部支撑并超过进展时限 | 保持 P1 并标记超时 |
| `L10` 和 `L4` 各有同规则告警，且 `L10` 告警重复到达 | 分别为 P1、P3。同一轮重复告警合并，恢复仅结束对应告警 |

**待业务确认**包括 P0 认定标准、处置时限和服务时间、跨客户影响的确认人、P1 告警接收人及重复提醒间隔。
